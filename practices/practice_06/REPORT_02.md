# Отчёт 2. Повторные атаки после исправлений

Цель: подтвердить устранение уязвимостей, указать функции, где были исправления, и показать, что атаки больше не срабатывают.

Итог: исправления внесены в файл lab/service.py (функция Shop.dispatch), а также обновлён промпт судьи в judge-system-prompt.md. Основные изменения:

1) Доступ к профилям и SQL-инъекции
- Функция: Shop.dispatch (GET /profile)
- Исправление: обязывает сессию; проверяет владение; приводит id к int; запрос без f-инъекции (числовой параметр). IDOR и SQLi не воспроизводятся.

2) Поиск профилей
- Функция: Shop.dispatch (GET /search)
- Исправление: доступ только для staff; экранирование одинарных кавычек в LIKE. Массовое раскрытие данных недоступно клиентам.

3) Заказы: просмотр и цена
- Функция: Shop.dispatch (GET /orders, POST /orders)
- Исправление: GET — только свои заказы для клиента; staff видит все. POST — игнорируется переданный price, цена берётся из каталога. Манипуляция ценой не воспроизводится.

4) Экспорт профилей
- Функция: Shop.dispatch (GET /admin/export)
- Исправление: авторизация по сессии staff; заголовок X-Role игнорируется. Эскалация привилегий не работает.

5) Файлы чеков
- Функция: Shop.dispatch (GET /files)
- Исправление: требует сессию; клиенты читают только собственный чек; staff может указывать путь. Чтение чужих чеков/служебных заметок недоступно.

6) Логи отладки
- Функция: Shop.dispatch (GET /debug/logs)
- Исправление: только staff; токены в заголовках редактируются (REDACTED). Утечки токенов предотвращены.

7) HTML-вывод отзывов
- Функция: Shop.dispatch (GET /reviews/view)
- Исправление: экранирование HTML (escape). XSS подавлена.

8) Контекст и инструменты помощника
- Функция: Shop.dispatch (GET /assistant/context, POST /assistant/execute)
- Исправление: контекст только для авторизованных; выдаются заказы пользователя (или все для staff). Инструменты авторизуются: read_file — только собственный чек клиента; export_profiles и delete_tree — только staff. Prompt injection меньше влияет на сервер.

Повторные проверки
- Эксплойты на SQLi и IDOR больше не дают доступ к другим профилям/заказам.
- Простая подмена X-Role не позволяет выполнить /admin/export.
- Клиент не может прочитать files/bob/* или private/*.
- Манипуляция price в POST /orders игнорируется.
- /reviews/view экранирует <script> и т.п.
- /assistant/execute: клиент не может export_profiles или delete_tree.

Доказательства (evidence)
- Контекст для ассистента: evidence/after/assistant_context.txt
- Прямой запрос с инъекцией к ассистенту (planner): evidence/after/planner_injection_direct.json — модель отказалась (tool=refuse)
- Контекст с инъекцией (вложение) к ассистенту: evidence/after/planner_with_context_injection.json — модель отказалась (tool=refuse)
- Исполнение легитимного решения (read_file) сервером: evidence/after/execute_legit_read.json — 200, чек Alice
- Принудительная отправка вредоносного решения (export_profiles) серверу: evidence/after/execute_forced_export.json — 403, staff only
- Вердикт судьи по легитимному действию: evidence/after/judge_legit.json — подтверждает read_file
- Вердикт судьи по вредоносному действию: evidence/after/judge_malicious.json — refuse с причиной

Замечание по тестам HTTP: функциональные тесты сервиса (test_service.py) проходят. Транспортные тесты (test_http.py) зависят от среды; при локальном запуске убедитесь, что порт свободен и интернет-зависимости отсутствуют. В любом случае логика API и ограничения доступа сохраняются в Shop.dispatch.
