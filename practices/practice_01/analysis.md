# Анализ процесса: AS IS и TO BE

## AS IS

Клиент отправляет HTTP POST на `/api/reviews` с полем `diff` (строка). Endpoint без валидации размера/схемы извлекает `diff` и вызывает `review_service.review(diff)`. Сервис формирует prompt простым включением diff и синхронно вызывает внешний LLM без таймаута/обработки ошибок. Ответ LLM возвращается как `{"comment": ...}`. Задержки и ошибки LLM приводят к 500. Нет логирования по OBS-1.


## TO BE

Добавить валидацию запроса (Pydantic) и ограничение размера diff (API-1 → 413). Перед вызовом LLM выполнить редакцию секретов (SEC-1). Вызов LLM обернуть в таймаут 10s и обработку ошибок (REL-1), вернуть структурированный ответ по OUT-1: `summary`, `risks<=3` с `file,line,evidence,risk`, `checks`. Вести логирование `request_id`, длительности и статуса (OBS-1). Endpoint объявляет `response_model`.

```mermaid
flowchart LR
    A[POST /api/reviews с diff] --> B[Валидация и 413 >20k]
    B --> C[Редакция секретов SEC-1]
    C --> D[Вызов LLM с таймаутом 10s]
    D --> E[Пост-обработка: OUT-1, <=3 риска, evidence]
    E --> F[Логирование OBS-1]
    F --> G[Ответ клиенту]
```

## Разница

| Что меняется | AS IS | TO BE | Как проверим изменение |
|---|---|---|---|
| Валидация и размер diff | Отсутствует | 413 при >20k | Интеграционный тест |
| Редакция секретов | Отсутствует | Санитайзер | Юнит-тесты на токены |
| Таймаут/ошибки LLM | Отсутствуют | 10s и контролируемый ответ | Симуляция таймаута |
| Формат ответа | {comment} | OUT-1 (summary, risks<=3, checks) | Схема/контракт тест |
| Логирование | Нет | request_id, длительность, статус | Проверка логов |
