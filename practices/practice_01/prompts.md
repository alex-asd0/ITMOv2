## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель: провести повторное ревью TRAINING_PR.diff по правилам репозитория и оформить результаты по файлам.
- Роль AI: reviewer, выявляет проблемы по diff и правилам из CASE.md, оформляет отчёты.

### 2. Входы и источники

- Обязательный вход: TRAINING_PR.diff.
- Разрешённые файлы и источники: practices/practice_01/TRAINING_PR.diff, practices/practice_01/CASE.md, шаблоны отчётов под practices/practice_01/.
- Context Pack — факты, правила, примеры и ограничения: см. CASE.md разделы «Правила репозитория», «Примеры комментария»; ограничения — не менять код приложения, работать только с указанными файлами.

### 3. Задача и артефакты

- Что сделать: выполнить ревью PR, найти и доказать ошибки/риски, заполнить отчёты.
- Что вернуть: подробное ревью в P1-02.md; обновлённые отчёты context/problem/analysis/product_management/project_management/adr/tests_*; запись MasterPrompt.md; обновлённая строка в prompts.md.

### 4. Формат результата

- Структура ответа: для каждого замечания — место (файл, строка), причина, аргументация, способ решения; в отчётах — заполненные таблицы/разделы по шаблону.
- Ограничения объёма: соблюдать структуру файлов; не добавлять лишние разделы; максимум три риска в финальном ответе сервиса согласно OUT-1 (как требование к системе).

### 5. Полномочия и запреты

- Разрешено: читать TRAINING_PR.diff и CASE.md; редактировать только отчёты в practices/practice_01/; запускать make install и make test.
- Запрещено: менять код приложения, создавать новые файлы вне указанных; добавлять неподтверждённые факты.

### 6. Рабочий процесс и остановка

- Шаги: прочитать diff и CASE.md; составить список проблем с доказательствами; заполнить файлы; запустить make install и make test.
- Когда остановиться и запросить человека: если обнаружены противоречия в CASE.md или недостаточно контекста в diff.

### 7. Проверки и evidence

- Как проверять утверждения: каждое замечание подтверждать строкой из diff или правилом CASE.md; избегать предположений.
- Какое evidence сохранить: ссылки на конкретные файлы/строки в описании, цитаты фрагментов diff при необходимости, ссылки на правила (SEC-1, API-1 и др.).

### 8. Definition of Done

- Задача закончена, когда: найденные ошибки доказаны; заполнены все отчёты; MasterPrompt.md содержит исходный промпт; prompts.md обновлён; make install и make test проходят успешно.
